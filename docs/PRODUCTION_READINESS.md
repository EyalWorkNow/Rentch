# Rentch Production Readiness

This app can now run safely without accidental public remote-state writes. Production features are enabled explicitly with `--dart-define` flags.

## Required Release Defines

Base production build:

```bash
flutter build ipa \
  --dart-define=RENTCH_ENV=production
```

Enable Google sign-in only after `lib/firebase_options.dart` is generated by FlutterFire for every target platform:

```bash
--dart-define=RENTCH_ENABLE_GOOGLE_SIGN_IN=true
```

Enable Appwrite image storage only after the storage bucket and file permissions are configured:

```bash
--dart-define=RENTCH_ENABLE_CLOUD_STORAGE=true
--dart-define=APPWRITE_ENDPOINT=https://fra.cloud.appwrite.io/v1
--dart-define=APPWRITE_PROJECT_ID=<project-id>
--dart-define=APPWRITE_STORAGE_BUCKET_ID=<bucket-id>
```

Do not enable remote app state in production until user-scoped auth and Appwrite table permissions are configured:

```bash
--dart-define=RENTCH_ENABLE_REMOTE_STATE=true
--dart-define=APPWRITE_DATABASE_ID=<database-id>
--dart-define=APPWRITE_APP_STATE_TABLE_ID=<table-id>
```

## Current Hard Requirements Before Store Release

- Generate real Firebase options with FlutterFire if Google login is part of the launch.
- Configure Appwrite/Firebase/Supabase backend with user-scoped records. The app must not use one global shared state document for production users.
- Configure cloud storage rules so users can only write their own profile/property photos and can only delete their own files.
- Replace debug signing with real Android keystore and Apple signing profiles.
- Verify final bundle IDs/package IDs: `com.rentch.app` for iOS/Android was applied as a production default.
- Add crash reporting and release monitoring before opening traffic.
- Add privacy policy, terms, photo-upload consent language, and account deletion flow.

## Verification Commands

```bash
flutter analyze
flutter test
flutter run -d <device-id>
```

Expected known warnings:

- Flutter currently warns that this iOS project still has CocoaPods integration while plugins are moving to Swift Package Manager.
- Some macOS plugins still do not support Swift Package Manager. This is not a runtime blocker for iOS/Android, but it should be tracked before desktop release.
