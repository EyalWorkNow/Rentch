01 שבעת משטחי האיסוף

כל מקום שבו אנחנו לומדים משהו על המשתמש — מהצהרה מפורשת ועד לחיצה חבויה. הפס בצד מסמן מצב: ירוק=עובד ומנוצל · כתום=נאסף חלקית/רדום · אדום=מת.

פרופיל מוצהר עובד · הליבה

TenantProfile → /profile/fields → users.searchProfile

המקור האמין ביותר. ~22 שדות שהמשתמש ממלא (תקציב, חדרים, כניסה, עיסוק, ילדים, רכב, גיל…). מסנכרן 12 מהם ל־searchProfile — מזין את eligibility gate ו־cohort.

אותות חיפוש חיים עובד · real-time

SmartSearch.cohortSignals → query params

~18 אותות שנחלצים מטקסט החיפוש (household, oleh, wfh, vibe…) ומזינים דירוג לפי cohort. המחווט הכי טוב במערכת — אבל חסר־זיכרון: מחושב לכל חיפוש מחדש, לא נשמר.

אירועי מעורבות נאסף · write-only

EventService → rently-events

~30 סוגי אירועים עשירים: swipes, dwell, גלילת פרטים, מדיה, שינויי פילטר, יצירת קשר, מיקום, comparison. מעוצב יפה ומחווט — אבל אף שורת קוד לא קוראת את הטבלה בחזרה.

לייקים ופסים א־סימטרי

property_likes · property_views · rently-events

לייק → טבלה חוצת־משתמשים (popularity גלובלי + לידים לבעל הדירה). פס → אירוע בלבד, אין טבלת שלילה. למידה מקומית (UserSignals+FTRL) לומדת מהחלקות — אבל על המכשיר בלבד.

יומן דירוג מת · בלי תוויות

rently-search-log

שורה לכל impression עם וקטור פיצ'רים + outcome. אבל outcome תמיד 'impression', query תמיד ריק. סינק אימון ל־LightGBM שלא קיים, ואף אחד לא קורא.

Persona מתוחכם רדום בשרת

rently-persona · PersonaProfile

המודל הכי חכם: confidence + דעיכה 180 יום + פתרון קונפליקטים. consent-gated. אבל בשרת הוא write-only / owner-read — הדעיכה והביטחון רצים רק מקומית, ואף אחד לא קורא אותו בזמן דירוג.

חיפושים שמורים טבלה ריקה

rently-saved-searches

אין נתיב כתיבה לטבלת השרת → היא ריקה → התראות ה־FCM שסורקות אותה אף פעם לא נורות. המנגנון המקומי (התראה במכשיר) עובד, אבל חד־מכשירי ולא מזין את הפיד.

04 מה להוסיף — ואיך זה עוזר להתאמה אישית

ממודר לפי מאמץ. ההזדמנות הגדולה היא שרוב הנתונים כבר נאספים — צריך רק לסגור את המעגל ולקרוא אותם בחזרה.

QUICK

הדלקת מה שכבר בנוי

ימים · שינויי חיווט
  1. להזין את הלומד (FTRL) מהדק הראשי
    היום רק חיפוש מזין אותו. למלא את _pfvCache לקלפי הדק ולהעביר את הלומד ל־relevance. התאמה: המשטח שבו רוב ההחלקות קורות מתחיל ללמוד את הטעם האישי.
  2. להדליק embeddings + kNN בפיד הראשי
    ENABLE_EMBEDDINGS=1 ולקרוא ל־/search/knn בפיד. התאמה: שכבת הדמיון הסמנטי (כבר כתובה) עוברת מ־0.5 קבוע להשפעה אמיתית — "דומה למה שאהבת".
  3. למלא תוויות ל־search-log
    להשלים outcome מלייק/פס/יצירת־קשר (join לפי sessionId+propertyId) ולשמור את טקסט החיפוש האמיתי. התאמה: הופך סינק מת לסט אימון אמיתי — הבסיס ל־ranker נלמד.
MEDIUM

סגירת המעגל בשרת

שבועות · לוגיקה חדשה
  1. להזרים התנהגות חזרה לדירוג בשרת
    לצבור affinity לתגיות/אזורים מ־events (או להעלות את UserSignals המקומי). התאמה: הפיד בשרת נעשה אישי — לא רק ה־cohort הסטטי.
  2. לאחד את שלושת מאגרי הפרופיל
    לקרוא את persona (עם הדעיכה) בזמן דירוג, ובאמת להשתמש ב־confidence. התאמה: המאגר החכם מפסיק להיות סינק מת; העדפות טריות שוקלות יותר מישנות.
  3. אות שלילה אמיתי
    לרשום פסים כאות מדורג ולהוריד דפוסים שנדחו. התאמה: המערכת לומדת גם ממה שהמשתמש לא רוצה, לא רק ממה שאהב.
  4. למלא יותר מפתחות cohort
    לאסוף sector/דתיות/oleh/משקיע ב־onboarding או דרך העוזר. התאמה: מתקן את "זנב ה־cohort הגס" — יותר משתמשים מקבלים קבוצה מדויקת.
BIG

יכולות חדשות

חודשים · תשתית
  1. שכבת צריכה / אנליטיקה
    ETL מ־events → מחסן; funnels/retention/DAU; ה־LightGBM ranker שהקוד כבר רושם עבורו. התאמה: אפשר סוף־סוף למדוד ולאמן על התנהגות אמיתית.
  2. Collaborative filtering
    "שוכרים כמוך אהבו גם…" — למידה חוצת־משתמשים מהתנהגות שהועלתה. התאמה: ה־lift הגדול ביותר — התאמה מבוססת דמיון בין משתמשים, לא רק פרופיל מוצהר.
  3. זמן־שהייה כאות דירוג
    להדליק את מאגר ה־dwell (חסום ב־build-define) ולהזין שהייה לדירוג. התאמה: תשומת לב חבויה = עניין אמיתי, מעבר ללחיצה מפורשת.
  4. הסכמה + פרטיות + observability
    consent על איסוף גולמי, מחיקת GDPR, מטריקות מובנות ו־A/B. התאמה: אפשר לשחרר ולמדוד שיפור בביטחון — בלי זה כל שינוי הוא ניחוש.

המהלך בעל המנוף הגבוה ביותר — ✅ בוצע

זו הייתה ההמלצה, והיא מומשה: ההתנהגות שנאספת מוזנת עכשיו בחזרה לתוך הדירוג — הלומד מוזן מהדק, CF item-item חי, ה-search-log מתויג, ומנוע LightGBM (Python→Lambda) בנוי ומאומת. האפליקציה כבר לא מסווג סטטי בלבד — היא מערכת לומדת שרק מחכה לנפח דאטה כדי להדליק את המודל בפקודה אחת (activate.sh). מה שנותר הוא מעלה-הזרם: מחסן אנליטיקה/BI וקריאת ה-persona בזמן דירוג.
